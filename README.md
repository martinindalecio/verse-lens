# Verse Lens

A Bible reader that explains the world around a passage. Select one or more verses and get an explanation of the BSB section that holds them, with your selection highlighted inside it.

Written by AI (Claude), labeled as such:

- **Setting**: who is speaking, to whom, where, and when
- **Historical and cultural background**: each claim shows what it rests on (the text itself, an ancient source, archaeology, or scholarly reconstruction) and a confidence level
- **How traditions read it**: Catholic, Orthodox, Reformed, Jewish, and other readings side by side, clearly labeled as interpretation rather than fact
- **Open questions** where scholars disagree

From reference data, each labeled with its source:

- **What's around it**: the neighbouring sections, by the BSB's own headings
- **Parallel passages and cross references**: the BSB's parallels and OpenBible.info's best-voted references
- **Key words** in the original Hebrew, Aramaic, or Greek (STEPBible)
- **People in the section**, identified from STEPBible TIPNR

Scripture text is the [Berean Standard Bible](https://berean.bible/), which is in the public domain. Cross references: [OpenBible.info](https://www.openbible.info/labs/cross-references/), CC BY. Context is generated by Claude (`claude-opus-5-5`) with structured outputs.

## Run it

```bash
npm install
neon env pull                # writes DATABASE_URL / DATABASE_URL_UNPOOLED to .env.local
node --env-file=.env.local scripts/load-people.mjs   # loads people data into Neon (safe to re-run)
# add ANTHROPIC_API_KEY to .env.local; optionally DAILY_GENERATION_CAP (default 200, 0 = off)
npm run dev
```

Open http://localhost:3000.

## How it works

| Piece | Where |
| --- | --- |
| Bible text, one JSON file per book | `data/bsb/` (built by `scripts/build-bible.py`) |
| BSB section headings and parallel passages, one JSON file per book | `data/sections/` (built by `scripts/build-sections.py`) |
| Cross references, one JSON file per book (OpenBible.info, CC BY: top 10 per verse, votes >= 1) | `data/crossrefs/` (built by `scripts/build-crossrefs.py`) |
| Original-language words per verse (Strong's ids) and lexicon | `data/words/<book>.json`, `data/words/lexicon.json` (built by `scripts/build-words.py`) |
| Book list and chapter loading | `src/lib/bible.ts` |
| Context schema and API response type (shared by API and UI) | `src/lib/context-schema.ts` |
| Section units (long sections split into parts of at most 30 verses) | `src/lib/units.ts` |
| Data parts of an explanation (neighbours, cross references, key words, people) | `src/lib/passage-data.ts` |
| Prompt, Claude call, cache, daily generation cap | `src/lib/context.ts` |
| `POST /api/v1/context` logic | `src/lib/context-handler.ts` |
| Tests (Vitest; database tests use PGlite with `db/schema.sql`, the model is mocked) | `src/**/*.test.ts` |
| API v1 (`/api/v1`): `books`, `books/{book}/chapters/{n}`, `person`, `POST context`, `schema` | `src/app/api/v1/`, helpers in `src/lib/api.ts` |
| Reader and context panel | `src/app/read/[book]/[chapter]/page.tsx`, `src/components/` |

The reader sends its selection; the server finds the BSB section holding its first verse (sections over 30 verses are split at their subheadings, else at chapter boundaries, else into even parts) and explains that unit. The verse text always comes from `data/bsb/`. Claude only writes what data can't answer (summary, setting, historical and cultural context with a basis and confidence, interpretations by tradition, open questions) and is told who the people in the passage are. Neighbouring sections, cross references, key words and people come from data files and the people tables and are returned alongside, under `data`, separate from `ai`. Explanations are stored once per unit in Postgres (`section_context`) and served to everyone; at most `DAILY_GENERATION_CAP` new ones are generated per UTC day (`generation_days`), after which the API answers `429 daily_cap_reached` until midnight UTC while saved ones keep working. See `docs/DESIGN.md` for the reasoning and `TODOS.md` for what's next.

## Regenerating the Bible data

```bash
curl -LO https://raw.githubusercontent.com/scrollmapper/bible_databases/master/formats/json/BSB.json
python3 scripts/build-bible.py BSB.json

curl -LO https://ebible.org/Scriptures/engbsb_usfm.zip
python3 scripts/build-sections.py engbsb_usfm.zip

curl -LO https://a.openbible.info/data/cross-references.zip
python3 -I scripts/build-crossrefs.py cross-references.zip
```

Original-language words (STEPBible TAGNT Greek NT and TAHOT Hebrew OT; both files say CC BY 4.0, the script refuses any file that does not). The raw files are not committed, because STEPBible asks that copies not be reposted:

```bash
mkdir -p /tmp/stepbible
base="https://raw.githubusercontent.com/STEPBible/STEPBible-Data/master/Translators%20Amalgamated%20OT%2BNT"
get() { curl -fL -o "/tmp/stepbible/$1.txt" "$base/$2.txt"; }
get "TAGNT Mat-Jhn" "TAGNT%20Mat-Jhn%20-%20Translators%20Amalgamated%20Greek%20NT%20-%20STEPBible.org%20CC-BY"
get "TAGNT Act-Rev" "TAGNT%20Act-Rev%20-%20Translators%20Amalgamated%20Greek%20NT%20-%20STEPBible.org%20CC-BY"
for r in Gen-Deu Jos-Est Job-Sng Isa-Mal; do
  get "TAHOT $r" "TAHOT%20$r%20-%20Translators%20Amalgamated%20Hebrew%20OT%20-%20STEPBible.org%20CC%20BY"
done
python3 -I scripts/build-words.py /tmp/stepbible
```
